Retrieval-Augmented Generation, or RAG, is a technique that combines information retrieval with text generation. Instead of relying purely on what a language model memorized during training, RAG retrieves relevant passages from an external knowledge base at query time and feeds those passages into the model as context.

The typical RAG pipeline has four stages. First, documents are collected and loaded from sources such as PDFs, web pages, or databases. Second, documents are split into smaller chunks, since embedding models and language models both have limited context windows and smaller chunks improve retrieval precision. Third, each chunk is converted into a dense vector embedding using a transformer-based encoder model. Fourth, embeddings are stored in a vector database that supports fast similarity search, such as FAISS, Pinecone, or Weaviate.

At query time, the user's question is embedded using the same encoder model used for the documents. The system then performs a nearest-neighbor search to find the top-k most similar chunks. These chunks, along with the original question, are passed to a large language model, which generates an answer grounded in the retrieved text.

A major benefit of RAG is that it reduces hallucination by grounding answers in retrieved evidence, and it allows the system to cite its sources. It also allows knowledge to be updated without retraining the model, since new documents can simply be added to the vector store. Chunk size and overlap are important tuning parameters: chunks that are too large dilute relevance, while chunks that are too small lose context.
